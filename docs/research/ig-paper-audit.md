# IGCSE 0478 Paper 2 SQL audit

Research date: 24 October 2026. Target syllabus: Cambridge IGCSE Computer Science 0478, examinations 2026–2028.

## Scope and method

The audit reviewed SQL questions in 21 distinct question papers and their 21 matching mark schemes. For each of 2023, 2024 and 2025, the sample includes February/March variant 22, May/June variants 21/22/23 and October/November variants 21/22/23. Every counted paper contains SQL tasks. Mark schemes and subquestions are not counted as additional papers.

Cambridge/UCLES-authored PDFs were read through public mirrors. The research used PDF text extraction and cross-checked the relevant questions, tables and marking points. Where keyword searches missed completion answers, question numbers and table names located the material. The November 2024 variant 21 question was checked through a web PDF reader after a direct download failed.

Duplicate checks used year, session, variant, question number and SQL scenario. All 21 identifiers are unique and the selected SQL tasks have distinct contexts. Similar query structures recur across papers. Analysis concerns the SQL sections rather than unrelated algorithm questions or whole-file hash deduplication.

The links below identify the original Cambridge documents. The machine-readable record is [ig-papers.json](ig-papers.json). Page references are one-based PDF page numbers, matching the printed pages reviewed.

## Syllabus and historical evidence

[The 2026–2028 syllabus, section 9.4, page 30](https://www.cambridgeinternational.org/Images/697167-2026-2028-syllabus.pdf) covers single-table queries, field selection, FROM, conditions, ascending/descending sorting, SUM, COUNT, AND, OR and reading results. Database foundations include fields, records, basic types and primary keys.

The syllabus defines the teaching scope. Explicit sorting directions and OR remain required even though they were absent from this sample. Historical NOT conditions and the exact-string LIKE answer are recorded as question-specific alternatives.

- Teach complete SELECT statements, exact field names, quoted text, numeric and explicit Boolean comparisons, SUM/COUNT, AND/OR and ORDER BY. Explain the equivalent ASCENDING/ASC and DESCENDING/DESC spellings.
- Interpret Boolean aliases using the declared field type. Record bare Boolean conditions, reordered AND conditions and equivalent filters against their specific sources.
- Keep multi-table queries, DDL, data maintenance, GROUP BY, AVG and wildcard LIKE in the appropriate advanced scope. MIN/MAX are outside the implemented syllabus function set.

## Teaching and implementation findings

- Distinguish record counts from quantity totals. The canned-stock question in s24/21 requires SUM; s23/22 and s24/22 provide direct comparisons with COUNT.
- Normalise TRUE/FALSE, YES/NO, Y/N and T/F only for Boolean fields. Preserve ordinary text such as a text-field value of No.
- Preserve exact identifiers, including Price$ and Rate$.
- Treat projection, filtering and sorting separately. The w24/23 and w25/22 tasks sort using fields omitted from the output.
- Check result order according to each task. The s25/23 mark scheme explicitly accepts any order for its three selected fields. A query without ORDER BY has no general row-order guarantee.
- Check additional datasets to catch missing conditions, hard-coded values and incorrect aggregates that happen to match the sample.
- Read PDF layouts carefully: the s23/22 explanatory expressions omit SELECT, w23/22 has an extracted trailing comma, and w25/21 uses a matching diagram.
- Link historical alternatives to their individual questions. The original exercises use automated formative feedback based on their stated requirements.

## Observations across the sample

The selected SQL tasks contain =, >, >= and <> comparisons and several default ascending sorts. They do not contain explicit ASC/DESC/ASCENDING/DESCENDING directions, OR, wildcard LIKE, multi-table joins or data-definition/maintenance statements. Syllabus requirements remain the basis of the curriculum alongside this sample evidence.
