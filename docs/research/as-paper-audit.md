# AS & A Level 9618 Paper 1 SQL audit

Research date: 24 October 2026. Target syllabuses: Cambridge International AS & A Level Computer Science 9618, examinations 2026 and 2027–2029.

## Scope and method

The audit reviewed the SQL tasks in 20 distinct papers and their 20 corresponding mark schemes, spanning 2021–2025. Cambridge-authored PDFs were obtained from the PapaCambridge mirror, extracted with pypdf, and cross-checked by question, marking point and accepted alternative. Each selected paper contains SQL, DDL or DML tasks with distinct question content.

The matching tasks in 9618_s21_13 and 9618_s21_11 are duplicates, as are 9618_w21_13 and 9618_w21_11. Only variant 11 is counted in each pair. Papers 9618_s23_13 and 9618_w23_12 were screened but not included. Incomplete paper/mark-scheme pairs were excluded.

The machine-readable record is [as-papers.json](as-papers.json). Page numbers are one-based PDF pages matching the reviewed printed pages. Each record links to both documents and includes original analysis and syntax notes.

## Syllabus relationship

- [9618 2026 syllabus](https://www.cambridgeinternational.org/Images/697372-2026-syllabus.pdf), section 8.3, pages 26–27.
- [9618 2027–2029 syllabus](https://www.cambridgeinternational.org/Images/721397-2027-2029-syllabus.pdf), section 8.3, pages 26–27.
- [Official subject page](https://www.cambridgeinternational.org/programmes-and-qualifications/cambridge-international-as-and-a-level-computer-science-9618/).

Both syllabus windows cover creating databases, creating and altering tables, primary and foreign keys, and the types CHARACTER, VARCHAR(n), BOOLEAN, INTEGER, REAL, DATE and TIME. Queries involve at most two tables, selection, filtering, sorting, grouping, inner joins, SUM, COUNT and AVG. Data maintenance includes insertion, deletion and updating. This SQL foundation belongs to AS and continues within the full A Level qualification.

The syllabus also establishes requirements such as ORDER BY, AVG and DELETE FROM that were not represented by the selected SQL tasks. This audit supplies no syllabus evidence for HAVING, DISTINCT, subqueries, outer joins or window functions.

## Execution and grading findings

1. Accept semantically equivalent explicit joins and comma joins with conditions, while respecting the fixed structure of completion questions. See s21/12, w23/11, s24/13 and s25/11–13.
2. Execute DDL changes in the actual database. The s24/11 and s24/12 questions add foreign keys to existing tables; w22/11 adds two fields after one ADD.
3. Enforce composite primary keys, non-NULL keys and foreign keys. The w24/11 table requires a two-field primary key.
4. Handle single- and double-quoted exam text. Preserve errors for missing quotes: s23/12 explicitly identifies them as a mistake.
5. Compare dates chronologically after interpreting the specified notation. Hash-delimited day/month/year dates appear in s23/12 and w24/12–13; w23/13 uses a quoted date. Test inclusive and exclusive boundaries.
6. Distinguish Boolean state from text. The s21/12 example uses Boolean Yes/No; w24/12 stores Y/N as characters. Apply conversions by field type.
7. Support evidenced LIKE alternatives in context. The w22/11 mark scheme accepts * and %, and w22/13 uses %. Convert wildcard syntax only inside LIKE patterns.
8. Check values and target records for INSERT and UPDATE. Papers w22/12 and s25/13 allow INSERT with or without a field list; s25/12 updates two fields with comma-separated assignments.
9. Preserve table identifiers such as ORDER from s25/11 and s25/13. Quote them internally according to syntactic position while preserving ORDER BY.
10. Enforce meaningful grouping. The s25/11 query groups by a customer primary key and selects the dependent name. The s25/13 task accepts grouping by ID or name. Use additional records to expose accidental merging of different customers with identical names.
11. Require an aggregate heading where the task asks for one, accepting suitable alternative aliases.
12. Record type alternatives against their evidence. CHAR, INT, VARCHAR without a length, CURRENCY, TEXT and FLOAT occur in some mark schemes. Teach the selected syllabus types as the default.
13. Compare query results and database state rather than SQL text. Check values, columns, requested ordering, grouping, headings, structure and modified data. Use additional datasets to catch coincidental sample matches.

## Targeted validation cases

- Date boundaries and neighbouring years for year ranges and strict comparisons.
- Correct joins where matching identifiers appear in several tables.
- Actual state after inserts, updates, added fields, foreign keys and composite primary keys.
- Leading-zero text identifiers, quoted text, Boolean fields and Y/N character fields.
- Equivalent explicit and comma joins, plus required aggregate headings.
